## 二、固件 bin 文件（可直接烧录）

### 2.1 一键烧录用（推荐）

| 文件 | 大小 | MD5 | 烧录地址 |
|---|---|---|---|
| `dist\s3_host_merged.bin` | 1,146,880 B | `281ea46b8d2672c8ad7b234267f44391` | **0x0** |
| `dist\c5_slave_merged.bin` | 1,411,264 B | `e41836edaa298b412f83cef6a8801709` | **0x0** |

> `*_merged.bin` 已把 bootloader + 分区表 + app 拼成一个文件，**从 0x0 一次写完即可**。
> C5 的 bootloader 虽然实际落在 0x2000，但合并镜像开头已用 0xFF 填充，所以对外仍是 0x0 起烧。

### 2.2 只更新应用（保留已保存的 WiFi 配置）

| 文件 | 大小 | MD5 | 烧录地址 |
|---|---|---|---|
| `s3_host\build\esp32_s3_nat_repeater.bin` | 1,081,344 B | `df25e4597981d8581e7bf8a705605e35` | **0x10000** |
| `c5_slave\build\esp32_c5_coprocessor.bin` | 1,345,728 B | `84f5f6141ed7fe25e3846e07004eefb9` | **0x10000** |

> 只烧 app 到 `0x10000` 不会碰 `0x9000` 的 NVS，**已配好的 SSID/密码不会丢**。

### 2.3 烧录命令

```powershell
# esptool 位置
$esptool = "C:\Espressif\python_env\idf6.1_py3.13_env\Scripts\esptool.exe"

# ---- S3（COM15，USB 原生口）----
# 全量：合并镜像从 0x0
& $esptool --chip esp32s3 -p COM15 -b 460800 write-flash 0x0 dist\s3_host_merged.bin
# 增量：只更新应用，保留 NVS
& $esptool --chip esp32s3 -p COM15 -b 460800 write-flash 0x10000 s3_host\build\esp32_s3_nat_repeater.bin

# ---- C5（COM12）----
# 【必须先按住 S3 复位】否则 S3 的 GPIO42 复位脉冲会反复打断 esptool
python tools\flash_c5.py          # 脚本已内置"S3 保持复位"逻辑，推荐用它
# 手动等价命令：
& $esptool --chip esp32c5 -p COM12 -b 460800 write-flash 0x0 dist\c5_slave_merged.bin
```

> **C5 首次烧录或换过固件分区，先 `erase-flash` 再写**，否则可能残留错误镜像导致
> `invalid header: 0x????????` 无限重启。

### 2.4 烧录地址对照（记不住就看这张）

| 芯片 | bootloader | 分区表 | app | NVS |
|---|---|---|---|---|
| ESP32-S3 | `0x0` | `0x8000` | `0x10000` | `0x9000` |
| ESP32-C5 | **`0x2000`**（RISC-V，不是 0x0） | `0x8000` | `0x10000` | `0x9000` |

## 四、编译

```powershell
# 环境（每次新开终端都要设）
$env:IDF_PATH       = "C:\esp\v6.1\esp-idf"
$env:IDF_TOOLS_PATH = "C:\Espressif"
$env:IDF_PYTHON_ENV_PATH = "C:\Espressif\python_env\idf6.1_py3.13_env"

cd C:\wifi\frontend2.0
powershell -ExecutionPolicy Bypass -File tools\build.ps1 -Target s3 -Jobs 1   # 只编 S3
powershell -ExecutionPolicy Bypass -File tools\build.ps1 -Target c5 -Jobs 1   # 只编 C5
powershell -ExecutionPolicy Bypass -File tools\build.ps1 -Target all -Jobs 1  # 全编 + 生成 dist
```

> **必须 `-Jobs 1`**：多线程会卡死在 esp-hosted 的代码生成步骤。
> 结束时若出现 `OSError: ESP_ROM_ELF_DIR ...`，**是假失败**（只影响 coredump 后处理），镜像已生成，看时间戳即可。

## 五、关键配置（改这些要重编）

### S3（`s3_host\sdkconfig`）

| 配置项 | 值 | 说明 |
|---|---|---|
| `CONFIG_ESP_HOSTED_HOST_SPI_CLK_MHZ` | 40 | SPI 时钟；换长线要降到 26/20/10 |
| `CONFIG_ESP_HOSTED_HOST_SPI_CLK_GPIO` | 12 | CLK |
| `CONFIG_ESP_HOSTED_HOST_SPI_MOSI_GPIO` | 11 | MOSI |
| `CONFIG_ESP_HOSTED_HOST_SPI_MISO_GPIO` | 13 | MISO |
| `CONFIG_ESP_HOSTED_HOST_SPI_CS_GPIO` | 10 | CS |
| `CONFIG_ESP_HOSTED_HOST_HANDSHAKE_GPIO` | 17 | 握手 |
| `CONFIG_ESP_HOSTED_HOST_DATA_READY_GPIO` | 4 | 数据就绪 |
| `CONFIG_ESP_HOSTED_HOST_RESET_GPIO` | 42 | 复位 C5（JTAG MTMS，占用后失去硬件调试） |
| `CONFIG_LWIP_TCP_WND_DEFAULT` | 65535 | TCP 接收窗口（默认 5760，是吞吐瓶颈） |
| `CONFIG_LWIP_TCP_SND_BUF_DEFAULT` | 65535 | 发送缓冲 |
| `CONFIG_LWIP_TCP_RECVMBOX_SIZE` | 32 | 收包队列 |
| `CONFIG_LWIP_IPV4_NAPT` | y | NAT 必需 |

### C5（`c5_slave\sdkconfig`）

| 配置项 | 值 | 说明 |
|---|---|---|
| `CONFIG_EH_TRANSPORT_CP_SPI_GPIO_CLK` | 3 | CLK |
| `CONFIG_EH_TRANSPORT_CP_SPI_GPIO_MOSI` | 7 | MOSI |
| `CONFIG_EH_TRANSPORT_CP_SPI_GPIO_MISO` | 2 | MISO |
| `CONFIG_EH_TRANSPORT_CP_SPI_GPIO_CS` | 10 | CS |
| `CONFIG_EH_TRANSPORT_CP_SPI_GPIO_HANDSHAKE` | 1 | 握手 |

## 七、验收一句话

**烧完 `dist\` 里两个 bin → 手机连 `ESP32` / `12345678` → 打开 `http://192.168.4.1` → 扫描选网 → 保存重启 → 徽标变绿即成功。**

此时 `curl http://192.168.4.1/api/status` 应满足：
`sta_linked=true`、`has_ip=true`、`sta_ip` 非 `0.0.0.0`、`reason=0`。
