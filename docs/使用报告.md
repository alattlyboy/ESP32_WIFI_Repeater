# 使用报告 · ESP32-S3 + ESP32-C5 双芯片 WiFi 中继器

| 项目 | 内容 |
|---|---|
| 固件版本 | **2.2.0** |
| 报告日期 | 2026-11-16 |
| 部署地点 | 校园网环境（`SXYYKJXY-Student-5G`，开放网络 + Portal 形态） |
| 硬件 | ESP32-S3-N16R8（主机）+ ESP32-C5（射频前端）+ 7 根杜邦线 + 两路 USB 供电 |
| 结论 | **可用**。C5 收 5G、S3 发 2.4G，手机连上即可上网；校园网无需企业认证配置 |

---

## 一、它解决的是什么问题

一句话：**把"只有 5G 信号好、但设备只支持 2.4G"的场景打通。**

- 校园网/宿舍路由器的 5G 覆盖好、干扰少，但很多 IoT 设备（老手机、摄像头、扫地机、打印机）只有 2.4G 射频；
- 或者 2.4G 频段挤了十几个邻居 AP，实测吞吐只剩几百 Kbps。

本机让 **C5 用 5G 连上级**（抗干扰、低延迟），**S3 用 2.4G 发热点**（兼容一切设备），中间用 SPI 把以太网帧搬过去。对客户端来说，它就是一个普通的 2.4G 路由器。

> 为什么必须是两颗芯片：ESP32-C5 是 **1T1R 单射频双频**，同一时刻只能在 2.4G 或 5G 其中一个频段上收发；ESP32-S3 只有 2.4G 射频，连不上 C5 开的 5G 热点。所以"一颗收 5G、一颗发 2.4G"必须用**有线（SPI）**互联，不能无线级联。

## 二、实际使用流程（3 步）

### 第 1 步：接线 + 上电

按 `docs/接线图.svg` 接 7 根线（CLK / MOSI / MISO / CS / HANDSHAKE / DATA_READY / RESET，外加 GND 至少 2 根），**线长 ≤ 10cm**。S3 插 USB 供电即可，C5 由 S3 的 3V3 供电。

上电后 S3 会打印握手结果，看到下面三行就说明接线没问题：

```
slave chip id: 0x17 (esp32c5)
RPC version negotiated: V2
host=3.1.0 coprocessor=3.1.0 (match)
```

### 第 2 步：连热点 + 打开配置页

手机/电脑连 `ESP32`（默认密码 `12345678`），浏览器打开 **http://192.168.4.1**。

### 第 3 步：选上级网络

点「扫描」→ 点你要连的网络 → **选认证方式** → 填密码 → 保存并重启。

认证方式三选一，判断标准是"手机连它时是什么表现"：

| 手机上的表现 | 选这个 |
|---|---|
| 不用输密码就连上，随后浏览器弹登录页 | **开放网络（网页认证 Portal）** |
| 连的时候系统弹窗要用户名 + 密码 | 校园网 / 企业版 802.1X |
| 要输一个固定 WiFi 密码 | 密码（WPA2/WPA3） |

保存后约 10~15 秒，页面顶部徽标变绿「已联网」，此时手机就能上网了。

## 三、实测数据（本次部署）

### 3.1 链路状态

| 指标 | 实测值 |
|---|---|
| 上行 SSID / 频段 | `SXYYKJXY-Student-5G` / 5GHz，信道 40 |
| 上行信号 | -48 ~ -52 dBm（良好） |
| 上行 IP | `10.151.47.228`（校园网内网段，正常） |
| 认证方式 | 开放网络（`eap_enable=2`），**无需 802.1X、无需门户登录** |
| 下行热点 | `ESP32`，2.4GHz 信道 6，11n |
| 客户端 IP | `192.168.4.2/24`，网关 `192.168.4.1` |
| 客户端 DNS | 学校下发 `59.49.49.49` + 备用 `119.29.29.29` |
| 空闲内存 | 187 KB（连接稳定后） |

### 3.2 连通性

| 测试 | 结果 |
|---|---|
| 客户端 → 网关 ping（20 包） | 20/20，0% 丢失，平均 31ms |
| DNS 解析 `www.baidu.com` | 正常（180.101.49.44 / 180.101.51.73） |
| HTTPS `www.baidu.com` | 200，0.46s |
| `generate_204`（手机判"已联网"用） | 204 |
| 设备页面 `/` `/app.js` `/style.css` `/api/status` | 全 200 |

### 3.3 吞吐（同机同源对照）

| 场景 | 单流 | 四流并发合计 |
|---|---|---|
| 直连校园网（5G，516Mbps PHY） | 155 KB/s | 570 KB/s ≈ 4.5Mbps |
| 经本机中继（2.2 最终配置） | 217 KB/s | **416 KB/s ≈ 3.3Mbps** |

**怎么读这组数**：单流那个 155 KB/s 是**学校按账号限速**（直连也一样），不是中继拖累；
中继的聚合吞吐达到直连的 73%。换到不限速的家用宽带上会明显更快。

按 3.3Mbps 算实际体验：**1080p 视频（约 3~5Mbps）会自适应到 720p 流畅，微信/网页/文档无压力。**

## 四、能做什么

| 场景 | 是否支持 | 说明 |
|---|---|---|
| 中继（5G 上行 → 2.4G 下行 + NAT） | ✅ | 本固件主体功能，单层 NAT、单 DHCP、一个网段 |
| 普通家用路由（WPA2/WPA3 密码） | ✅ | 扫描后填密码即可 |
| 校园网开放网 + 网页认证（Portal） | ✅ | 选「开放网络」；实测本校直接可用、无需登录 |
| 校园网 / 企业网 802.1X（PEAP/TTLS） | ✅ | 已实现，需要填用户名密码（本校用不到） |
| 多设备共享一个账号 | ✅ | 所有客户端经 NAPT 共用设备那一个上行 IP |
| 网页配置 / 扫描 / 状态曲线 | ✅ | `http://192.168.4.1`，20KB 前端无外部依赖 |
| 断线自动重连 | ✅ | 指数退避 1→2→4→…→30 秒；有 IP 但 15 秒没通就主动重连 |
| 识别"到底是哪一步坏了" | ✅ | 设备侧自检直接给 `204` / `302→门户` / `TCP 不通` 三种结论 |

## 五、不能做什么（别踩坑）

| 需求 | 现实 | 原因 |
|---|---|---|
| 当 VPN 客户端（翻墙/回校内） | ❌ 本版未内置 | WireGuard 需要你自己的服务端，且 S3 上纯软算只有 2~6Mbps；半成品塞进去只会让你在"哪一步坏了"上浪费时间。把 VPN 配在手机/电脑或上级路由上更稳 |
| OpenVPN / L2TP / PPTP | ❌ | ESP32 上跑不动，也没有可用组件 |
| 自动填校园网门户表单 | ❌ | 各校门户协议自研、带验证码和加密参数，硬编码必然到处失败。登录这一步交给 NAT 后面的任意一台设备做，一次即可 |
| 上传 802.1X 客户端证书（EAP-TLS） | ❌ | 无证书上传界面；需要证书的学校请用「电脑开热点共享」 |
| 同时收 2.4G 和 5G | ❌ 物理限制 | C5 是单射频，同一时刻只能守一个频段 |
| 扫描时不断网 | ❌ 物理限制 | 单射频扫别的信道时必须离开当前信道，上行会断 1~2 秒（自动恢复） |
| 带 20 台以上设备 | ⚠️ 不建议 | 实测建议 ≤ 8 台，工程里上限设 10（RAM 所限） |

## 六、运维建议

1. **长期跑要不要重启？** 不需要。链路状态是事件驱动 + 2 秒一次的幂等守护，漏事件会自愈。只有改配置时才重启。
2. **看日志先看这三行**：
   - `STA_RMT: uplink got ip: x.x.x.x` —— 上行真的通了
   - `MAIN: NAPT enabled on AP` —— NAT 开了
   - `MAIN: [net] HTTP 204` —— 出口真的能上网
3. **"连上了但没网"排查顺序**：先看网页「上级 IP」是不是 `--`，再看那行人话提示；IP 有了还打不开，多半是 DNS（改「自定义」填 223.5.5.5）。
4. **扫描变慢/扫不到**：默认只扫 5G 非 DFS 常用信道（36~48、149~165），一个都没扫到会自动回退全信道（会慢到 10 秒左右）。
5. **换更长的排线后频繁重连**：把 `CONFIG_ESP_HOSTED_HOST_SPI_CLK_MHZ` 从 40 降到 26 / 20 / 10。
6. **想改热点名/密码**：网页里改「热点设置」，或长按 BOOT 键恢复出厂。
