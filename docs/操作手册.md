# ESP32 双频中继器 · 操作手册（2.1）

面向要**改配置、调性能、排查故障、二次开发**的人。只想把它用起来，看 `使用说明书.html` 就够。

> **2.1 相对 2.0 改了什么**
> 1. **修「连着热点却上不了网」**：链路状态改成事件驱动（不再拿 `get_ap_info` 猜，一次 RPC 抖动就会把好连接拆掉重连），NAPT / 默认出口 / DNS 改成 2 秒一次的幂等「网关守护」，漏事件也能自愈。
> 2. **企业版 802.1X**：PEAP-MSCHAPv2 / TTLS / TLS，网页可配，专治校园网、公司网（reason 210 / 202）。
> 3. **扫描快 2~4 倍**：主动扫描 + 每信道 40~80ms + 按频段限定信道位图 + 8 秒结果缓存。
> 4. 网页直接显示**断开原因码的人话**，不用再猜。
> 5. C5 固件打开 `ESP_HOSTED_CP_FEAT_WIFI_EXT_ENT`（不开的话企业版 RPC 返回 NOT_SUPPORTED）。

## 1. 系统架构

```
┌──────────┐  2.4G 空口   ┌─────────────────────┐   SPI 7 线   ┌──────────────┐  5G/2.4G 空口  ┌──────────┐
│  手机     │ ──────────▶ │ ESP32-S3            │ ───────────▶ │ ESP32-C5     │ ─────────────▶ │ 上级路由  │
│  IoT     │             │ SoftAP + DHCP + NAPT│              │ STA only     │                │          │
└──────────┘             │ Web UI + 自动重连     │ ◀─────────── │ 无应用逻辑    │ ◀───────────── │          │
                         └─────────────────────┘              └──────────────┘                └──────────┘
```

**分工原则**

| | ESP32-S3 | ESP32-C5 |
|---|---|---|
| 角色 | 路由器本体 | 无线网卡 |
| 射频 | 2.4GHz SoftAP | 5GHz / 2.4GHz STA |
| 三层功能 | NAT、DHCP、DNS 下发 | 无 |
| 内存 | 512KB SRAM（+8MB PSRAM 可选） | 384KB SRAM |
| 负载 | Web、状态轮询、客户端表 | 只跑 WiFi 固件 + RPC |

**关键约束（改代码前必须知道）**

1. `esp_wifi_remote` 的 RPC 在从机未就绪时会**长时间阻塞**。HTTP handler 里绝不能调它 —— httpd 默认单任务串行，一个 handler 卡住，整站（含 css/js）都不响应，网页就停在"读取中"。
   → 所有远端状态由 `remote_sta.c` 的后台任务（`sta_poll`，2 秒一次）写进静态变量，HTTP 只读变量。
2. **初始化与连接必须分两步**。首次配网时 NVS 里没有 SSID，若 `init` 只在"有 SSID"时执行，就死锁：没 SSID 不 init → 没射频不能扫描 → 扫不到就永远没 SSID。
   → `app_main` 里无条件 `remote_sta_init()`；用户保存后再 `remote_sta_connect()`。
3. 两端 Wi-Fi 类型同名不同义（`wifi_config_t` 等），**不能混在同一个编译单元**。本工程用两个文件隔离：`local_ap.c` 只碰本地 `esp_wifi.h`，`remote_sta.c` 只碰 `esp_wifi_remote.h`。

## 3. 编译

环境：**ESP-IDF v6.1**（`C:\esp\v6.1\esp-idf`，工具在 `C:\Espressif`）。

```powershell
powershell -ExecutionPolicy Bypass -File tools\build.ps1            # 两个都编
powershell -ExecutionPolicy Bypass -File tools\build.ps1 -Target s3 # 只编 S3
powershell -ExecutionPolicy Bypass -File tools\build.ps1 -Target c5 # 只编 C5
```

脚本做三件事：`set-target` / `reconfigure` → `ninja -j 2` → `esptool merge-bin` 输出到 `dist/`。

## 5. HTTP API

所有接口无鉴权（仅内网可达）。响应 `Content-Type: application/json`，均带 `Cache-Control: no-store`。

### `GET /api/status`

```json
{
  "fw": "2.1.0",
  "ap_ssid": "ESP32-NAT",
  "ap_channel": 6,
  "clients": 2,
  "client_list": [
    {"mac":"A4:CF:12:34:56:78","rssi":-52,"phy":"11n"}
  ],
  "sta_ssid": "MyHome-5G",
  "sta_configured": true,
  "sta_linked": true,
  "has_ip": true,
  "remote_ready": true,
  "reason": 0,
  "rssi": -58,
  "channel": 36,
  "sta_ip": "192.168.1.23",
  "band_mode": 2,
  "eap_enable": false,
  "eap_method": 0,
  "eap_username": "",
  "eap_identity": "",
  "eap_phase2": 0,
  "eap_skip_cert": true,
  "dns_mode": 0,
  "dns1": "223.5.5.5",
  "dns2": "119.29.29.29",
  "hist": [-58,-57,-59,...],
  "uptime_s": 3821,
  "free_heap": 143216
}
```

- `has_ip`：**只有它为 true 才真的能上网**（`sta_linked` 只代表空口关联上了）
- `reason`：最近一次 802.11 断开原因码（15=密码错/握手超时，201=找不到，210=需要企业版认证）
- `hist`：60 点信号历史（2 秒/点 ≈ 最近 2 分钟），`0` 表示那一刻断线
- `channel` > 14 即 5GHz

### `GET /api/scan`

立即返回，不阻塞：

```json
{"code":0,"state":"running"}
```

`state`：`running` / `notready`（C5 未就绪）/ `err`。

### `GET /api/scan_result`

前端每 700ms 轮询一次：

```json
{"state":"done","code":0,"list":[{"ssid":"Campus-EDU","rssi":-55,"ch":36,"secure":true,"eap":true}]}
```

`state`：`idle` / `running` / `done` / `err` / `notready`。`eap=true` 表示这是企业版网络。
`GET /api/scan?force=1` 强制重扫；不带 `force` 且距上次成功扫描 < 8 秒时直接返回缓存。

### `POST /api/config`

```json
{"sta_ssid":"MyHome-5G","sta_pass":"********","ap_ssid":"ESP32-NAT","ap_pass":"12345678","band_mode":2,"ap_channel":6,"dns_mode":0}

// 企业版（校园网）
{"sta_ssid":"Campus-EDU","eap_enable":1,"eap_method":0,"eap_phase2":0,"eap_skip_cert":1,
 "eap_username":"202312345","eap_pass":"********","eap_identity":"","dns_mode":1,"dns1":"10.10.0.1"}
```

密码字段**省略或留空 = 不修改**。返回 `{"code":0}`，800ms 后自动重启。

### `POST /api/reboot` / `POST /api/factory`

分别重启 / 擦除 NVS 后重启。返回 `{"code":0}`。

## 6. 串口日志

两块板都用 115200。S3 的关键行：

| 日志 | 含义 |
|---|---|
| `AP: SoftAP up: ... (ch6, auth=3)` | 热点起来了 |
| `HTTP: web UI on http://192.168.4.1/ (fw 2.0.0)` | 网页服务正常 |
| `STA_RMT: remote wifi ready: STA started` | C5 链路通了（**最关键的一行**） |
| `MAIN: NAPT enabled on AP (客户端可以上网了)` | NAT 打开成功 |
| `STA_RMT: uplink got ip: 192.168.x.y` | 上行拿到 IP，**这一行出现了才算真能上网** |
| `STA_RMT: uplink down, reason=15 (4WAY_HANDSHAKE_TIMEOUT/密码错)` | 断开原因，人话已打在括号里 |
| `MAIN: dhcp dns -> 223.5.5.5` | DNS 已下发给客户端 |
| `STA_RMT: connect 'xxx' (attempt 3, backoff 4000ms)` | 退避重连中（1→2→4→…→30 秒） |
| `STA_RMT: associated but no ip in 15s, reconnecting` | 关联成功但 DHCP 失败，主动重连 |
| `MAIN: [diag] scan -> 8 ap(s)` | 开机自检扫描（验证信道位图没把信道滤掉） |
| `STA_RMT: remote init failed: 0x...` | **C5 没通**：SPI 接线 / 供电 / 固件 |
| `MAIN: factory reset by button` | 长按 BOOT 触发恢复出厂 |

C5 侧：

| 日志 | 含义 |
|---|---|
| `coprocessor ready` | CP 固件正常，等待主机 |
| 什么都没打印 | 供电问题 / 没刷 CP 固件 / 处于下载模式 |

## 7. 性能调优

### 7.1 实测数据（2.2，ESP32-S3 + C5，校园网 5G 回程）

对照实验：同一台电脑、同一个下载源（阿里云镜像），分别在「直连校园网」和「经本机中继」下测。

| 场景 | 单流 | 四流并发合计 |
|---|---|---|
| 直连校园网（5G，516Mbps PHY） | 155 KB/s | 570 KB/s ≈ 4.5Mbps |
| 经中继（2.2 优化前：SPI 10MHz + TCP 窗口 5760） | 126 KB/s | **120 KB/s ≈ 1.0Mbps** |
| 经中继（2.2 优化后：SPI 40MHz + TCP 窗口 65535） | 217 KB/s | **416 KB/s ≈ 3.3Mbps** |

结论：**单流是校园网按账号限速**（直连也只有 155KB/s，约 1.2Mbps），中继在单流上不再拖累；
聚合吞吐从 1.0 → 3.3Mbps，达到直连的 ~73%。

### 7.2 关键参数

| 参数 | 默认（IDF） | 本工程 | 为什么 |
|---|---|---|---|
| `CONFIG_LWIP_TCP_WND_DEFAULT` | 5760 | **65535** | 5760B 只有 4 个 MSS，RTT 20ms 时单流上限 ≈ 2.3Mbps，多流互相挤占 |
| `CONFIG_LWIP_TCP_SND_BUF_DEFAULT` | 5760 | **65535** | 同上，发送侧 |
| `CONFIG_LWIP_TCP_RECVMBOX_SIZE` | 6 | **32** | 6 个包就丢，突发流量直接卡顿 |
| `CONFIG_LWIP_TCPIP_RECVMBOX_SIZE` | 32 | **64** | 同上 |
| `CONFIG_ESP_HOSTED_HOST_SPI_CLK_MHZ` | 10 | **40** | 隧道带宽是最大瓶颈：10MHz 下聚合卡在 1Mbps |

> 40MHz 对布线有要求：**线长 ≤10cm、GND 至少 2 根**。若日志出现
> `spi transfer failed` / 频繁重连，按 40 → 26 → 20 → 10 逐级回退，找到这块板子的稳定上限。
> 本机用 10cm 杜邦线跑 40MHz 稳定（连续 30 分钟无重传错误）。

### 7.3 还能怎么调

| 项 | 做法 | 收益 / 风险 |
|---|---|---|
| 热点信道 | 网页里选 1 / 6 / 11 里最干净的那个 | 避开邻居干扰，通常 +20% |
| 上行频段 | 优先 5GHz | 抗干扰，但穿墙差；信号 < -70dBm 时反而不如 2.4G |
| PSRAM | `CONFIG_SPIRAM=y` + `MODE_OCT` + `SPEED_80M` | 开 `LWIP_WND_SCALE` 才需要（窗口可超 64K）；**非 Octal PSRAM 的板子会反复重启** |
| 客户端上限 | `local_ap.c` 的 `max_connection = 10` | 实际超过 8 台容易掉线（RAM 所限） |

**注意**：`LWIP_WND_SCALE` 在 IDF 里依赖 `SPIRAM_TRY_ALLOCATE_WIFI_LWIP`，本工程没开 PSRAM，
所以窗口用 65535（不带 scale 的上限）。要再往上必须先把 PSRAM 配好。

## 8. 已知问题

### esp-hosted 3.1.0 的编译 bug

`port/os/include/eh_host_port_wifi.h` 里判断 `wifi_5g_channel_mask` 字段是否存在时，只看了"从机有没有 5G"，没看"主机自己有没有这个字段"。S3 是 2.4G-only，结构体里没这个成员 → 编译失败。

已打补丁。组件被重新下载覆盖后，重跑：

```powershell
powershell -ExecutionPolicy Bypass -File patches\apply.ps1
```

### 扫描会短暂断流

C5 单射频，扫描时必须离开当前信道，上行会断 2~3 秒。这是物理限制，不是 bug。

## 9. 排障决策树

```
网页打不开？
├─ 手机连上 ESP32-NAT 了吗？ ── 没有 → 看 S3 串口有没有 "SoftAP up"
└─ 连上了，页面白屏？ ── 换个浏览器 / Ctrl+F5；串口看 httpd 是否启动

页面能开，徽标「C5 未就绪」？
├─ S3 串口有 "remote init failed"？
│  ├─ C5 串口完全没输出 → 供电 / 没刷固件 / 按住 BOOT 进了下载模式
│  └─ C5 有 "coprocessor ready" → SPI 接线错。逐根对照接线图，重点查 HANDSHAKE / DATA READY
└─ 串口有 "remote wifi ready" 但仍未就绪 → 版本不匹配，重刷两边固件

能连上，但没网？
├─ 上级 IP 是 -- → 上行没连上。看扫描列表里目标 SSID 的 RSSI
├─ 上级 IP 正常但打不开网页 → DNS 没下发。重启一次（让 STA 先连上再起 DHCP）
└─ 能 ping IP 不能解析域名 → 同上，DNS 这条链断了

速度慢 / 丢包？
├─ 偶发丢包 → SPI 线太长或时钟太高，降到 10MHz、剪短线、多接地
├─ 稳定但只有 2~5Mbps → 检查是否还在 eppp 后端（应该走 hosted）
└─ 信号弱 → 挪位置，RSSI 目标 > -65dBm
```

## 10. 二次开发

**换引脚**：改两边 `sdkconfig.defaults` 的对应项，`build.ps1` 重编。注意 S3 侧避开 GPIO 0/3/19/20/26~37/43~46（strapping / USB / Flash / PSRAM / 串口）。

**改前端**：`s3_host/main/www/`，纯静态文件，编进固件，改完重编即可。不要引入需要构建的框架。

**加 API**：在 `web_server.c` 的 `uris[]` 里加一条，handler 里**只读缓存**。要拿远端实时数据，先在 `remote_sta.c` 的后台任务里采样存变量。

**改热点行为**：`local_ap.c` 的 `wifi_config_t`。想加 WPA3、隐藏 SSID、客户端隔离（`ap.ap.max_connection`、`esp_wifi_set_inactive_time`）都在这里。

**CP 固件升级**：重跑 `idf.py create-project-from-example "espressif/esp_hosted:<版本>:slave"`，`set-target esp32c5`。**host 组件和 CP 固件版本必须配套**（都 ≥ 3.1.0），差太大会卡在 `esp_hosted_init()` 且只打一行日志。

## 11. 企业版 802.1X（校园网 / 公司网）

### 11.1 原理与链路

```
C5 的 supplicant（跑在 C5 上，不在 S3）
   │  ① EAPOL-Start → AP
   │  ② PEAP 隧道（TLS）→ ③ 内层 MSCHAPv2 校验学号密码
   │  ④ 四次握手 → ⑤ DHCP 拿 IP
   ▼
S3：只负责把 "身份/用户名/密码" 通过 RPC 下发，然后把拿到的 IP 当默认出口 + 开 NAPT
```

EAP 的 TLS 握手在 C5 内部完成，**不占用 SPI 隧道带宽**，所以企业版不会拖慢转发。

### 11.2 C5 固件必须开的开关

`sdkconfig`（不是 defaults，是实际生效的那个文件）里这三条缺一不可：

```
CONFIG_ESP_HOSTED_CP_FEAT_WIFI=y
CONFIG_ESP_HOSTED_CP_FEAT_WIFI_EXT_ENT=y     # 2.1 新增：企业版 RPC
CONFIG_ESP_WIFI_ENTERPRISE_SUPPORT=y          # IDF 默认 y
```

没开 `..._EXT_ENT` 时，S3 日志会是：

```
STA_RMT: enterprise enable failed: 0x105 —— C5 固件要打开 ESP_HOSTED_CP_FEAT_WIFI_EXT_ENT
esp_eap_client_remote_weak: esp_wifi_remote_sta_enterprise_enable unsupported
```

`0x105` = `ESP_ERR_NOT_SUPPORTED`。

### 11.3 网页怎么填

| 字段 | 校园网常见值 | 说明 |
|---|---|---|
| 认证方式 | 校园网 / 企业版 802.1X | 选这个之后密码框会变成 EAP 表单。**先确认不是开放网络，见 11.5** |
| EAP 方法 | PEAP | 90% 的学校；少数用 TTLS |
| TTLS 内层 | MSCHAPv2 | 只有选 TTLS 才生效 |
| 用户名 | 学号 / 工号 | 不是邮箱前缀，按学校说明填 |
| 密码 | 上网密码 | 与 WiFi 密码不是一回事 |
| 匿名身份 | 留空 | 学校要求 `anonymous` 时才填 |
| 服务器证书 | 不校验 | 学校自签证书，选"校验"会一直 AUTH_FAIL |
| DNS | 自定义 → 学校 DNS | 校园网常屏蔽公共 DNS，这一步很关键 |

### 11.4 为什么不直接抄 esp32_nat_router

`esp32_nat_router` 是 **单芯片 STA+AP**，EAP 直接跑在本机的 supplicant 上，一行
`esp_wifi_sta_enterprise_enable()` 就完事。

本方案是 **双芯片**：射频在 C5，supplicant 也在 C5，S3 只能通过 esp-hosted 的 EAP RPC 遥控。
所以必须满足三个条件：

1. C5 的 CP 固件打开 `ESP_HOSTED_CP_FEAT_WIFI_EXT_ENT`（否则 RPC 根本不存在）
2. S3 打开 `CONFIG_ESP_WIFI_REMOTE_EAP_ENABLED=y`（否则本地用弱符号桩，永远 NOT_SUPPORTED）
3. host / CP 两端 esp-hosted 版本一致（本工程 3.1.0 / 3.1.0）

这三条现在都满足了，功能上与单芯片方案等价。

### 11.5 第三种形态：开放网络 + 网页认证（Portal）

**先分清「场景」和「认证方式」——这是最容易搞错的地方。**

"校园网/企业网"说的是**谁在用**，"认证方式"说的是**802.11 这一层要不要密码**。
同一个学校，教学楼可能是 Portal 开放网，宿舍可能是 802.1X，实验室可能是 WPA2 密码。

判断只需要看一件事：**手机连它的时候，是弹密码框，还是直接连上后弹网页？**

| 手机上的表现 | 802.11 层 | 网页里该选 |
|---|---|---|
| 直接连上，随后浏览器自动弹登录页 | 开放（open / none） | **开放网络（网页认证 Portal）** |
| 连的时候系统弹窗要用户名 + 密码 | WPA2/WPA3-Enterprise | 校园网 / 企业版 802.1X |
| 要输一个固定 WiFi 密码 | WPA2/WPA3-Personal | 密码 |

Windows 上也可以导出已保存的配置来确认（`netsh wlan export profile ... key=clear`），
看这三个字段就够了：

```xml
<authentication>open</authentication>
<encryption>none</encryption>
<useOneX>false</useOneX>
```

`open + none + useOneX=false` = 开放网络。用"企业版"去连它，STA 会拿企业级安全去匹配一个
开放 AP，直接 **`reason=210 NO_AP_FOUND_W_COMPATIBLE_SECURITY`**（安全不兼容）——
所以那种情况**不是密码错，是模式选错**。

选「开放网络」之后的固件行为：

1. `threshold.authmode = WIFI_AUTH_OPEN`，密码字段强制清空（有密码反而连不上）
2. 关联 → 四次握手跳过 → DHCP 拿 IP → NAPT 打开，和普通中继完全一样
3. 上行 IP 一般是内网段（如 `10.x.x.x`），这是正常的

#### Portal 登录怎么过

设备本身没有浏览器，登不了门户页。可行路径有两条：

1. **NAT 后共用设备 IP（多数学校可用）**
   门户是按**源 IP** 授权的，而所有客户端经 NAPT 出去都是设备那一个 IP。
   所以随便一台客户端（手机/电脑）连上热点后打开任意网页，被跳到门户页，
   用学号登录一次，**设备这个 IP 就被放行**，其他客户端立刻一起能上网。
2. **先认证再中继（保底）**
   如果学校把 MAC 绑进认证（少见），就让设备的上行 MAC 先在电脑上认证一次，
   或者干脆用「电脑开热点共享」的方案。

判断属于哪种，看串口日志里这一行（2.2 新增的设备侧自检）：

```
[net] HTTP 204 —— 上行直接可以上网（无需门户认证）
[net] HTTP 302 被门户拦截 -> http://10.151.x.x:8080/portal?...
[net] TCP 80 连不上 (errno=118) —— 有 IP 但出不去
```

- `204`：完全不用管门户，直接能用
- `302 ... portal`：按上面第 1 条做，客户端浏览器登录一次
- `TCP 连不上`：IP 拿到了但上游没放行，通常就是"还没做门户认证"

> 注意：本固件**不替你自动填门户表单**。原因是门户协议各校自研、还带验证码/加密参数，
> 硬编码只会到处失败。登录这一步交给 NAT 后面的任意一台设备做，一次就够。

## 12. VPN：能做什么、不能做什么（重要）

### 12.1 结论先说

| 需求 | 能不能 | 说明 |
|---|---|---|
| 中继器（STA→AP 桥接 + NAT） | ✅ 已实现 | 本固件的主体功能 |
| 企业版 802.1X（校园网/公司网） | ✅ 已实现 | 见 §11 |
| 网页认证（Portal）穿透 | ✅ 天然支持 | 客户端流量经 NAPT 出去，Portal 看到的是本机 IP，登录一次全体可用 |
| **VPN 客户端（WireGuard）** | ⚠️ 需要额外集成，本版未内置 | 见 12.2 |
| OpenVPN / L2TP / PPTP | ❌ | 无可用组件，ESP32 上跑不动 |

### 12.2 WireGuard 的真实成本

技术上可行：S3 上跑一个 lwIP 的 WireGuard netif，把默认出口从 STA 网卡切成 WG 网卡，
AP 侧 NAPT 不动，客户端无感。

但要清楚三件事：

1. **要有服务端**。机场/商业 VPN 一般只给 OpenVPN 或自研协议，不给 WireGuard 配置；
   你得自己有 VPS（`wg genkey` 那一套），或者用支持 WG 的服务商。
2. **吞吐会掉**。S3 上 ChaCha20-Poly1305 纯软算，实测同类方案 3~8Mbps；
   本方案还要过 SPI 隧道，实际大概 2~6Mbps —— 刷视频够呛，网页/微信没问题。
3. **组件兼容性**。社区组件 `trombik/esp_wireguard` 最后更新在 IDF 5.x，
   在 IDF 6.1 上需要改几处 `esp_netif` 驱动注册代码才能编过，**且必须有服务端才能验收**。

所以本版没有把半成品塞进固件（塞进去只会让你在"到底哪一步坏了"上浪费更多时间）。
要上 WireGuard 的话，按这个顺序做，一步一验收：

```
① 先拿到一份能用的 wg0.conf（私钥 / 对端公钥 / Endpoint / AllowedIPs=0.0.0.0/0）
② 加组件：idf_component.yml 里加 trombik/esp_wireguard，编过一次修兼容问题
③ wg 起来后 esp_netif_set_default_netif(wg_netif)，NAPT 保持挂在 AP 上
④ 验收：客户端 ping 8.8.8.8 通 → nslookup 通 → speedtest 有 2Mbps 以上
```

### 12.3 现在就能用的替代方案

- **校园网/公司网本身要 VPN 才能出网**：把 VPN 配在**客户端**（手机/电脑）上，
  本机只做中继 —— 这是最省事、最稳的做法。
- **想让全屋设备共用一条线路**：把 VPN 跑在上级路由（OpenWrt + WireGuard）上，
  本机中继那个已经翻好的热点即可。

## 13. 扫描为什么能快（以及 2.2 找到的真凶）

| 优化 | 之前 | 现在 |
|---|---|---|
| 扫描类型 | 被动（等 beacon） | 主动（发 probe request） |
| 每信道驻留 | 默认 120ms（甚至 1500ms） | 30~50ms |
| **5G 信道位图** | `0x1FFFFFFE`，**含 DFS 52~64 / 100~144** | `0x3E0001E`，只扫 36~48 + 149~165 |
| 2.4G 信道 | 1~13 | 1~13（不变） |
| 隐藏 SSID | 扫 | 不扫 |
| 重复点击 | 每次真扫 | 8 秒内走缓存 |
| 扫不到时 | 直接返回空 | 自动回退**全信道**再扫一次（宁可慢一次，不漏 DFS 上的 AP） |

### 13.1 为什么要拿掉 DFS 信道

这是 2.2 之前扫描要 10.5 秒的真正原因，**不是驻留时间没生效**：

- DFS（Dynamic Frequency Selection）是气象/航管雷达频段，法规要求**先监听 110ms 以上**确认没有雷达，
  才能在该信道上发 probe；
- 原来那张位图把 5G 所有 bit 都置 1，等于把 52~64、100~144 这些 DFS 信道全拉进来被动驻留，
  光这一项就是 8~9 秒；
- 家用/校园 5G 实际几乎只落在 36~48 和 149~165，扫这 9 个信道就够。

### 13.2 实测

| 配置 | 耗时 |
|---|---|
| 2.1：全信道（含 DFS）+ 40/80ms | **10.5 s** |
| 2.2：非 DFS + 30/50ms | **2.7 s** |
| 8 秒内重复点击 | 毫秒级（走缓存） |

> 扫描时 C5 单射频必须离开当前信道，上行会断 1~2 秒，之后自动恢复 —— 物理限制，不是 bug。
> 已实测：扫描结束 `has_ip` 仍为 true、信道与 RSSI 自动恢复。

### 13.3 什么时候会"慢回去"

目标 AP 恰好在 DFS 信道上时：第一次扫描返回 0 个结果，固件会自动用全位图再扫一次，
这次会花 ~10 秒。日志里能看到：

```
STA_RMT: non-DFS 扫描 0 个 AP，回退全信道再扫一次
```

这是设计行为，不是卡死。
